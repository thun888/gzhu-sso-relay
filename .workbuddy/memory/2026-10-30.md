# 2026-10-30

## 完成

从零搭建 `gzhu-sso-relay`（Gin + gorm + PgSQL + Redis 的 SSO 中转，设计见 PLAN.md）。

### 上游接入层

- `internal/upstream/cas`：CAS 登录。取登录页 `lt` 与 `execution`，提交 `rsa`（strEnc 加密 `用户名+密码+lt`）、`ul`、`pl`、`lt`、`execution`、`_eventId=submit`；成功后落点标题为 `融合门户`。
- `internal/upstream/cas/des.go`：`des.js` 的逐位复刻。
- `internal/upstream/portal`：`Bootstrap`（GET 门户首页让 CAS 票据落地成本域会话）、`Profile`（`POST /up/up/gzhuStaffInfo/getPIThree {}`），只保留 `MOBILE→sub`、`USER_NAME→name`、`BELONG_CLASS→class`。
- `cmd/casprobe`：读 `GZHU_USERNAME` / `GZHU_PASSWORD`，跑通登录到取数全流程。

### 前端

- `web/` 是 React 19 + Vite 6 + Tailwind v4 + **shadcn/ui** 的 SPA，只有登录页。背景图 `web/public/background.webp`（铅笔稿校园线描，用户提供）。
- shadcn 通过 `components.json`（style new-york，cssVariables，iconLibrary lucide）管理，组件源码在 `web/src/components/ui/`，后续加组件用 `npx shadcn@latest add <name>`。
- 主题变量写在 `web/src/index.css` 的 `@theme inline` + `:root`，`--primary` 设为 `#0f7b43`，`--muted` 设为浅绿 `#f3f8f4`（右侧面板底色）。必须保留 `@custom-variant dark (&:is(.dark *))`，否则组件里的 `dark:` 会跟随系统深色模式。
- shadcn CLI 有个坑：它会把 `@/lib/utils` 误判成 npm 包 `cn` 并装一个同名依赖，同时把组件里的 import 改成 `from "cn"`。安装后必须检查并改回，删掉 `cn` 依赖。CLI 也不会自动写入主题变量，`init` 那部分要手工补。
- 登录卡片左右分栏：左侧表单，右侧预留文案；`server.login_panel.enabled=false` 时收成单栏窄卡片。文案通过 `GET /api/public/config` 下发，改配置即生效，不用重新构建前端。
- 构建产物 `web/dist` 已提交并由 `web/embed.go` 内嵌，`go build` 直接出单二进制；改前端后必须 `npm --prefix web run build` 再编译 Go。
- `npm install` 走默认源会超时，需加 `--registry=https://registry.npmmirror.com`。
- 注意：`min-h-full` 百分比高度链会断，布局用 `min-h-screen`。

### 地基层

- `internal/config`：改为 `config.yaml`（`gopkg.in/yaml.v3`），入口 `-config` 指定路径，缺省 `./config.yaml`。`config.yaml` 与 `data/` 已入 `.gitignore`，仓库内只放 `config.example.yaml`。`upstream.timeout` 支持 `30s` 这种时长写法（自定义 `Duration` 类型）。
- `server.email_domains` 是 `前缀 → 邮箱后缀` 的映射，按 sub 做**最长前缀匹配**（`"32"` 优先于 `"3"`）；键 `""` 匹配全部，作兜底。未命中时登录返回 `auth.ErrNoEmailDomain`，不会生成 `学号@` 这种残缺邮箱。
- `internal/store`：gorm 八张表 + `Migrate` + `Seed`（openid/profile/email 三个默认 scope）。
- `internal/cryptox`：AES-256-GCM（密文带 `v1:` 前缀便于轮换）、Argon2id 密码哈希。
- `internal/cache`、`internal/session`：Redis 客户端与 12 小时会话，cookie 名 `relay_session`。
- `cmd/relay`：Gin 服务、`/healthz` 同时探 PgSQL 与 Redis、优雅退出。

### 登录与 OIDC

- `internal/auth`：本地 Argon2id 校验优先；本地不匹配才回访上游，覆盖上游改密与首次登录。`Throttle` 限制 15 分钟内 5 次上游验证。
- `internal/oidc`：授权码 + PKCE、RS256 签发、`/.well-known/openid-configuration`、`/oidc/jwks|authorize|token|userinfo`。授权码存 Redis 且 `GETDEL` 一次性消费。scope 决定 claims，`profile` 带 `name`/`preferred_username`/`belong_class`，`email` 带 `email`/`email_verified`。
- `internal/httpapi`：`/api/login|logout|me`、`/login` 临时 HTML 登录页（React 上线后替换）、`/api/admin/*` 用户与用户组接口。
- `cmd/relayctl`：`client create|list|delete`、`user promote`。

### 授权准入链路

`/oidc/authorize` 现在依次检查：会话 → 用户组 → `oauth_clients.required_bindings`（缺绑定跳 `/?bind=<provider>&next=<authorize>`）→ `consents` 表里是否已覆盖所申请的 scope（未覆盖跳 `/consent?req=<id>`）→ PKCE → 发码。

- 待确认的授权请求存在 Redis（`oidc.Pending`，10 分钟），确认页只凭不透明 id 取用，避免伪造参数。
- `consents` 表按 (user_id, client_id) 唯一，授予时按 scope 合并。
- 绑定层 `internal/binding` 只依赖标准 OAuth2 授权码流程，provider 全部来自配置，新增来源不用改代码。`id_field`/`name_field` 指定对方 userinfo 里的账号标识与展示名。
- 绑定回调走 `GET /bindings/:provider/callback`，身份来自 Redis 里的 state，不依赖 cookie。
- **绑定完成后必须回到原授权请求**：`/` 的 `next` 参数在绑定成功（`?bound=`）时自动跳回，否则第三方应用会一直挂在等待状态。

### 管理后台

- `users.type`：0 普通 / 1 管理员；默认注册都是 0，首个管理员用 `relayctl user promote -id <学号>` 指定（用户需先登录一次才会入库）。
- 用户中心对 `type==1` 显示「管理后台」入口，`/admin` 页面按 `?tab=users|groups|clients` 分页。
- `/api/admin/*` 全部走 `RequireAdmin`，非管理员访问前端会跳回用户中心。
- 应用管理接口：`GET/POST /api/admin/clients`、`PATCH/DELETE /api/admin/clients/:id`、`PUT .../scopes`、`PUT .../groups`，另加 `GET /api/admin/scopes`、`GET /api/admin/bindings`（后者返回配置里可用的绑定源）。
- 客户端密钥在创建时生成并只返回一次，库里只存 Argon2id 哈希（`cryptox.NewSecret`）。

## 关键结论

- **`des.js` 不是标准 DES**：`generateKeys` 把 PC1 表按转置取位，K1 得 `1B02EFA6E5F6`，标准 DES 为 `1B02EFFC7072`。上游服务端与之匹配，因此不能用 `crypto/des`，必须逐位复刻。已用 Node 跑参考值逐条比对通过。
- 该实现依赖全局变量 `i/j/k`，移植时不能按标准 DES 简化。
- 实测 2026-10-30：登录成功，`newmy` 的 `MOBILE` 返回的是**学号本身**（11 位），不是手机号。
- 参考项目 `G:\Project\Course-Bullying-in-GZHU\` 的密码字段是 UTF-8 十六进制编码。
- gorm 把 `OAuthClient` 拆成 `o_auth_clients`，三个 OAuth 模型都需显式 `TableName()`。
- 迁移已在临时内嵌 Postgres 上验证通过：`profile_data` 为 `jsonb`，时间列为 `timestamptz`，两组联合索引符合 PLAN。生产库由用户提供后再跑。
