## 用户组区分上游与本地

- `groups.source`：`local`（默认，手工维护）/ `upstream`（由上游身份信息同步）。
- 同步只在真正访问上游后发生：`auth.saveUpstreamProfile` 存快照后调 `GroupRepo.SyncUpstream`，按 `USER_TYPE` / `UNIT_NAME` / `BELONG_MAJOR` 生成 `user_type:<值>`、`unit:<值>`、`major:<值>` 三个组，并整表替换该用户所有上游组成员，本地组不受影响。
- 后台上游组显示「上游同步」标签，隐藏成员编辑；接口层也拒绝改名/改标识/改成员。
- 注意：本地密码哈希命中时不访问上游，因此这类用户不会重新同步，只有本地校验失败走上游或首次登录才会更新。

## 登录成功后按概率刷新上游

- `upstream.refresh_rate`（默认 0.1，取值 0 到 1）：本地密码哈希命中的登录路径上，按该概率起 goroutine 回访上游，刷新 profile_data 与上游用户组。
- 只在这条快路径触发；首次登录、本地哈希不匹配回访上游时本来就会拉一次。
- 刷新走 `fetchUpstream`，不经过 Throttle，不占用账号的 5 次上游验证额度；失败只打日志，不影响登录结果。
- 实测 refresh_rate=1 时：登录 245ms 返回，后台约 1s 内完成，生成 3 个上游组并刷新快照 updated_at。

## 修复统一保存报「更新应用失败」

- 根因：`ClientRepo.Update` 用 map 形式 `Updates()`，GORM 的 `serializer:json` 只对结构体字段生效；裸 `[]string` 写 `redirect_urls`/`required_bindings`（jsonb）时驱动按 text[] 字面量编码，Postgres 报 `invalid input syntax for type json (SQLSTATE 22P02)`。此前 redirect_urls/required_bindings 的实时保存路径同样有此 bug，统一保存后才真正暴露。
- 用临时测试在真实库事务内复现并回滚验证：raw []string 失败、`json.Marshal` 后的 string 写入成功（两列均验证）。
- 修复：`Update` 内把所有 `[]string` 值先 `json.Marshal` 成字符串再写库。

## 能力盘点与同类产品对比

- 新增 `docs/gap-analysis.md`：按协议、令牌生命周期、应用治理、信任决策、身份源、安全合规、可观测、用户体验八组做逐项对比（对照 Keycloak / CAS / Casdoor / Logto / Authentik / Hydra / Dex / Authelia / Auth0）。

## 刷新令牌与令牌撤销（提交 18d5ffb）

- `internal/oidc/refresh.go`：不透明随机串（32 字节 base64url），Redis `relay:refresh:<token>` 存 RefreshGrant（user_id/client_id/scopes/auth_time），TTL 30 天；`relay:user-refresh:<学号>` 集合索引用于按用户清零。`Consume` 用 `GetDel` 实现轮转，重复提交返回 `invalid_grant`。
- `internal/oidc/revoke.go`：`POST /oidc/revoke` 按 RFC 7009，凭据有效时一律 200；refresh token 直接删，access token 按 sha256 摘要写入 `relay:revoked:*`，TTL 取剩余有效期。userinfo 每次校验撤销表（fail closed）。
- token 端点拆成 `exchangeCode` / `exchangeRefresh`，共同走 `issueTokens`；刷新路径不返回 nonce（OIDC Core 12.2），`auth_time` 沿用首次授权。刷新时重新检查用户状态与 `Clients.Allows`，支持 scope 缩小但不扩大。
- 管理员禁用账号时 `RefreshStore.RevokeUser` 与会话 `RevokeAll` 一并执行，避免重新启用后旧凭据复活。
- 已知边界：撤销只影响 relay 的 userinfo，下游离线验签仍会接受未过期 access token；未实现 offline_access，所有授权都发 refresh token。
- 实测：Redis 8.4 支持 GETDEL；本地起服务确认 discovery 输出 `revocation_endpoint`、`/oidc/revoke` 无凭据返回 401。

  - `UpdatePasswordHash` 只在上游验证通过后调用，顺带清标记。
